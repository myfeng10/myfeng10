# Outreach Playbook

## 核心流程

### 1. 先找 signal，不先拉 persona 名单

优先搜索最近 30–60 天的公开表达：

- `team Claude Code context`
- `agents duplicated work`
- `AI coordination overhead`
- `too many check-ins AI`
- `shared memory privacy`
- `Claude Code team workflow`
- `prompts in Slack`
- `agents don't know what teammates did`
- `stakeholder context AI`
- `context management biggest investment`

一个职位、公司规模或融资事件只能帮助 qualification，不能单独成为 outreach 理由。

### 2. 保存原始 hook

只保存与联系理由直接相关的原句或行为。不要先让 AI 总结整篇文章。

需要记录：

- 原文链接；
- 发布日期；
- 原始 hook；
- 这个 hook 暗示的 workflow；
- 哪些是事实，哪些只是我们的 hypothesis。

### 3. 根据 pain 分类

- **Repeated work：** 两个人或 agent 重复研究。
- **Context handoff：** 结果需要人工复制给队友。
- **Stakeholder coverage：** 需要频繁 meeting/check-in 才能跟上。
- **Fragmentation：** context 散落在 session、Slack、文档和 repo。
- **Privacy：** 不愿意把完整 AI history 共享给公司。
- **Staleness：** 共享 context 很快过期或互相矛盾。

### 4. 选择动作

- 对方正在公开提问：先 comment。
- 对方明确描述过强 pain：可以直接 DM。
- 对方是高级负责人：提供 workflow exchange 或 founder-led pilot，不强调礼品卡。
- 对方是个人开发者或普通用户：可以提供 $50 的研究感谢。
- 对方做邻近产品：邀请专家交流，不伪装成客户开发。

### 5. 第一条消息

结构：

1. 一个 hook。
2. 它引出的新问题。
3. 一个具体产品画面。
4. private-by-default 的边界。
5. 一个有限的 ask。

### 6. Discovery

不要先做完整 demo。先问：

1. 最近一次两个队友或 agent 重复做同一件事是什么时候？
2. 你们最后怎么发现的？
3. 那个结论现在存在哪里？
4. 谁需要知道它？为什么当时没有及时知道？
5. 为了让 stakeholder 跟上，你们增加了哪些 meeting、status update 或 check-in？
6. 如果自动共享 AI conversation，你最担心泄露什么？
7. 哪些信息应该自动共享，哪些必须由本人确认？
8. 如果做一个 3–5 人试验，什么结果会让你继续使用？

### 7. Demo 一个时刻

不要先展示完整 memory graph。

只演示：

1. Alice 从自己的 AI work 中选择一条 memory。
2. Alice 发布给 group。
3. Bob 在自己的 agent 里询问相关问题。
4. Bob 得到 Alice 的结论、身份和原始来源。
5. Alice 未发布的其他 conversation 不可见。

### 8. Pilot

建议 offer：

- 3–5 人；
- 一个 repo、project、account 或 workflow；
- 4–6 周；
- EchoMem 团队亲自设置；
- 免费；
- private by default；
- 每周一次简短反馈；
- 随时导出或删除；
- 预先约定成功指标。

成功指标示例：

- 少开了多少次纯 context-transfer meeting；
- 少做了多少次重复研究；
- stakeholder 获取答案需要多久；
- 发布和检索是否被实际使用；
- 是否发生误共享或 privacy 不适；
- 找到的 context 是否有 owner 和可信来源。

## Coverage：AI 与人的分工

AI 负责：

- 找公开 signal；
- 去掉没有 pain 的人；
- 保存原始 hook；
- 把 lead 分进 pain category；
- 根据人工模板生成初稿；
- 检查事实和链接；
- 提醒 follow-up。

人负责：

- 判断联系理由是否真的成立；
- 决定是否发送；
- 修改语气；
- 审核 privacy 或敏感推断；
- 处理所有真实回复；
- 做 discovery；
- 决定是否进入 pilot。

不要让 AI：

- 从个人主页直接生成奉承式开场；
- 猜测对方没有公开表达的 pain；
- 自动发送未经审核的高价值 lead；
- 自动回复已经产生兴趣的真人；
- 为了个性化而加入无关的私人信息。

## 第一轮执行目标

不要群发 100 封。

第一轮：

- 20 个经过评分的 lead；
- 其中至少 12 个达到 14 分以上；
- 5 个公开 comment；
- 10 个个性化 DM/email；
- 5 个专家或邻近产品交流；
- 目标得到 6–8 个回复；
- 完成 4–5 次 discovery；
- 找到 2 个小 pilot。
