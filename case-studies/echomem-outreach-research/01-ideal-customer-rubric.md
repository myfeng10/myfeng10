# Ideal Customer Rubric

## 一句话 ICP

2–50 人的团队中，至少两个人高频使用 Claude Code、Codex、Cursor、ChatGPT 或其他 agents；团队已经因为 AI context 无法在人和 agent 之间移动，而出现重复工作、额外会议、频繁 check-in、手工转述或 privacy 顾虑。

团队人数不是最重要的。公开表达过真实 pain，远比“符合某个职位或行业”重要。

## 必须区分的两类问题

### 强问题：EchoMem Group 应该解决

- “每个人的 agent 都在快速工作，但互相不知道做过什么。”
- “同一个问题被两个人或两个 agent 重复研究。”
- “为了让 stakeholder 跟上，需要增加 meeting、status update 或 check-in。”
- “有用的决定埋在某个人的 Claude/Codex session 里。”
- “我们在 Slack DM、文档和 prompt 之间手工搬运 context。”
- “我们想共享 agent learnings，但不能共享完整聊天记录。”
- “AI adoption 越高，coordination overhead 反而越明显。”

### 弱问题：不要当作主要购买信号

- 普通的小团队讨厌开会。
- 泛泛地抱怨管理成本。
- 想做 async work，但没有使用 AI 的团队工作流。
- 单纯想减少 standup。
- 对 AI memory 感兴趣，但没有实际协作场景。
- 只是在转发热门的 agent 或 GTM 内容。

普通的 meeting fatigue 只有在它明确来自“为了搬运 AI context 而开会”时，才是强信号。

## Lead 评分

满分 18 分。先根据公开证据评分，再决定是否研究和联系。

### 1. 明确表达过 pain：0–5 分

- 0：没有 pain，只是符合职位或公司类型。
- 1：泛泛讨论 AI、协作或生产力。
- 2：提到 context、handoff、重复工作或会议，但没有真实例子。
- 3：描述过具体问题或 workaround。
- 4：明确说问题带来了时间、质量或协调损失。
- 5：公开寻求解决方案、正在自建方案，或邀请别人交流这个问题。

### 2. 多人 AI 工作流：0–3 分

- 0：没有证据显示使用 AI。
- 1：一个人偶尔使用 AI。
- 2：多人使用 Claude Code、Codex、Cursor、ChatGPT 或 agents。
- 3：多个成员、多个 agent 或多个工具已经成为日常工作方式。

### 3. Context 必须跨人移动：0–3 分

- 0：纯个人 memory。
- 1：同一个人的多个 session 之间需要 context。
- 2：context 需要在两个人或不同职能之间移动。
- 3：经常跨工程、产品、销售、客户或 stakeholder 移动。

### 4. 已经付出协调成本：0–3 分

- 0：没有已知成本。
- 1：偶尔手工复制或整理。
- 2：依赖 Slack、文档、meeting、status update 或人工 summary。
- 3：明确出现重复工作、持续 check-in、额外会议或专门维护内部系统。

### 5. Privacy 与控制：0–2 分

- 0：没有 privacy 需求。
- 1：可能涉及私人 conversation、客户数据或敏感项目。
- 2：明确讨论过权限、安全、选择性共享、审计或数据边界。

### 6. 可接近性和时机：0–2 分

- 0：没有自然联系渠道，相关内容很久以前发布。
- 1：有公开渠道，或最近 90 天表达过相关问题。
- 2：最近 30 天主动发帖、提问、招聘、寻找方案或邀请反馈。

## 扣分项

- 纯思想领袖，没有真实 workflow：-2。
- 只是因为职位叫 CTO、VP Engineering 或 FDE：-2。
- 只抱怨普通会议，与 AI context 无关：-3。
- 自己正在销售直接竞争产品：-2；可以做专家访谈，但不当客户。
- 只有个人 session memory，没有跨人场景：-2。
- 找不到 legitimate reason to reach out：直接跳过，不发送。

## 决策线

- 14–18：立即个性化联系，优先争取 pilot。
- 10–13：值得联系，先公开 comment 或做 discovery。
- 7–9：继续观察，等待更强 signal。
- 0–6：跳过。

## 发送前必须写出的四句话

如果研究者无法清楚填写下面四项，就不应该联系：

1. **Signal：** 对方具体说了什么或做了什么？
2. **Pain hypothesis：** 这可能暴露了哪个真实 workflow 问题？
3. **EchoMem connection：** 为什么选择性共享 context 可能与此相关？
4. **Why now：** 为什么现在联系，而不是任何时间都可以联系？

## 最理想的早期客户

最优先：

- 3–15 人 AI-native startup；
- 工程、产品或 GTM 团队已经多人使用 agents；
- 创始人或负责人亲自使用 AI；
- 还没有很重的采购流程；
- 能选择一个小 workflow 做 3–5 人试验；
- 公开抱怨过 context fragmentation、handoff、重复研究或 AI coordination；
- 对“不能把完整 conversation 共享给公司”有直觉上的顾虑。

次优先：

- 更大公司的一个独立小组；
- FDE、solutions、pre-sales 或 customer engineering 团队；
- 多个 stakeholder 需要频繁了解客户或项目 context；
- 可以在单个项目、单个 account 或单个 repo 内做 pilot。
